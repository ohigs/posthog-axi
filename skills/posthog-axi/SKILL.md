# PostHog AXI

Generated by scripts/generate-skill.js.
Do not edit this file manually.

This community-maintained CLI is not endorsed by PostHog and has no official AXI status.
Run commands through the pinned GitHub package with npm exec.
No globally installed binary is required.
Node.js 20 or newer, npm, Git, and network access on first installation are required.
Never fetch posthog-axi from the npm registry.
Automatic self-update is disabled.
Run `npm exec --yes --package='git+https://github.com/ohigs/posthog-axi.git#v0.3.0' -- posthog-axi` to inspect current authentication and project scope.
Use scoped --help before calling a command.
Use the same npm exec prefix for every command, including help, pagination, and status hints that display a bare posthog-axi command.
Set POSTHOG_PROJECT_ID or --project explicitly.
A scoped personal key can allow project API access while the global projects list returns HTTP 403.

## Safety and output

Authenticate only with POSTHOG_PERSONAL_API_KEY.
Never put credentials in argv or files.
Use --host or POSTHOG_HOST and --project or POSTHOG_PROJECT_ID.
The default host is https://us.posthog.com.
Lists default to 25 items.
--limit accepts 1 through 100.
Counts distinguish returned items from total, which can be null.
TOON is the default output.
--json emits JSON.
--fields selects safe fields.
--full disables content previews, never redaction or row limits.
Query --sql and --file are exclusive.
SQL is not rewritten.
Use a SQL LIMIT and time range to bound computation.
No bulk export or query OFFSET pagination is supported.
Pending queries include a scoped query status command.
Failed queries exit 1.
Usage errors exit 2.
Errors are structured on stdout.
Pagination hints preserve host, project, fields, and output flags.
Do not follow raw API next URLs.
Known secret keys and the configured credential are redacted.
Arbitrary secrets in analytics business data cannot be detected.
Hook installation is deferred because SDK 0.1.13 does not safely quote executable paths in shell hooks.
Use the generated Agent Skill instead.
Complete queries report received response rows and returned display rows, not totals.
Complete describes finished execution, not exhaustive results.
backend_has_more is the upstream hasMore boolean or null when absent or null.
truncated is true if display rows were capped or backend_has_more is true.
False truncated with null backend_has_more does not prove backend completeness.
These fields apply to synchronous and completed asynchronous results.
--full never removes row limits.
Narrow SQL and the time range when the backend reports more rows.
Create and update use scalar flags and named query or targeting files.
Use scoped --help for supported inputs and exact permission scopes.
Creation is not guaranteed idempotent; writes are never retried automatically.
Use --dry-run for local credential-free previews.
It does not check remote permissions, state, version or policy.
Target-bound confirmations remain required.
Obtain operator approval before destructive changes.
Archive confirmations bind project, resource and ID.
Query replacement and membership replacement require their impact confirmations.
Flag targeting and activation require their own confirmations, including inactive creation with supplied targeting.
Insight archives remove subscriptions and linked alerts and hide tiles.
Query changes can also remove alerts.
Dashboard archives preserve insights but hide tiles and clear home/primary references.
These are not fully reversible operations.
Manage dashboard membership through insights --dashboards using the deprecated upstream dashboards field.
none clears membership.
A missing archived insight or dashboard is not proof of an already-completed archive.
Inspect before retrying an uncertain write.
Honor server approval and version conflicts and never bypass them through another endpoint.

## Safe resource fields

- projects accepts `id`, `name`, `timezone`, `created_at`, `primary_dashboard`.
- insights accepts `id`, `name`, `derived_name`, `description`, `short_id`, `last_refresh`, `filters`, `query`, `tags`, `favorited`, `dashboard_tiles`.
- dashboards accepts `id`, `name`, `description`, `pinned`, `tags`, `tiles`.
- flags accepts `id`, `key`, `name`, `active`, `filters`, `archived`, `version`.
- persons accepts `id`, `uuid`, `name`, `distinct_ids`, `properties`, `created_at`, `last_seen_at`.
- cohorts accepts `id`, `name`, `description`, `count`, `is_static`, `is_calculating`, `groups`, `filters`, `query`, `created_at`, `last_calculation`.
- annotations accepts `id`, `content`, `date_marker`, `scope`, `dashboard_id`, `dashboard_item`, `created_at`, `updated_at`, `deleted`.
- recordings accepts `id`, `distinct_id`, `start_time`, `end_time`, `recording_duration`, `active_seconds`, `inactive_seconds`, `start_url`, `click_count`, `console_error_count`, `viewed`, `ongoing`.
- events accepts `id`, `event`, `timestamp`, `distinct_id`, `properties`.
